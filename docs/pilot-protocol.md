# 파일럿 프로토콜 (사용성 테스트·가격 의향 조사)

목적: 이음이 "55–75세가 혼자 입력을 끝내고, 그 결과를 상담에 가져갈 만하다고 느끼는가"를 최소 규모로 확인한다. 표본이 작아 **통계적 결론이 아니라 문제 발견용**이다. 결과를 일반화해서 쓰지 않는다.

## 1. 대상과 규모

- 시니어 이용자 5명 이상 (만 55–75세, 가족과 재산을 직접 정리해야 하는 입장인 사람)
- 세무사 또는 변호사 1명 이상 인터뷰 (30분)
- 팀원 2명 중 1명은 진행, 1명은 기록

## 2. 시작 전 안내 (읽어 주기)

1. "실제 이름·계좌번호·실제 금액은 쓰지 마세요. 가명과 가상 금액으로 해 주세요."
2. "이 앱은 세금을 계산하거나 법적 판단을 하지 않습니다. 정보를 정리하는 도구입니다."
3. "테스트 대상은 제가 아니라 화면입니다. 막히면 그게 화면의 문제입니다."
4. 기록 동의: 화면 녹화는 하지 않고 메모만 한다. 이름 대신 P1–P5 번호를 쓴다.
5. 끝나면 "모든 데이터 삭제"를 이용자가 직접 눌러 지우게 한다. (기기를 빌려 쓴 경우 필수)

## 3. 과제 (도움 없이 진행, 막힌 지점만 기록)

| 번호 | 과제 | 성공 기준 | 시간 상한 |
|---|---|---|---|
| T1 | 가족 구성(가명)을 입력하고 "직접 확인"한다 | 가족 2명 이상 등록 + 확인 체크 | 3분 |
| T2 | 재산 3건(부동산·예금·채무 중 가상 값)을 기준일·확인상태와 함께 입력한다 | 3건 저장 | 6분 |
| T3 | 과거 증여 1건을 기록한다 | 1건 저장 | 3분 |
| T4 | "준비 점검"에서 부족한 항목 1개를 찾아 보완한다 | 점수 상승 확인 | 3분 |
| T5 | 상담 리포트에서 "재산·채무"를 빼고 미리보기를 확인한다 | 재산 정보가 사라진 것을 말로 설명 | 3분 |
| T6 | 글자를 더 크게 바꾸고 방금 한 입력을 지운다 | 바꾸기 + 삭제 | 2분 |

기록 항목: 완료 여부, 소요 시간, 도움을 받은 횟수, 망설이거나 잘못 누른 곳, 소리 내어 한 말(그대로).

## 4. 사후 질문 (1–5점, 5가 가장 긍정)

1. 혼자서 끝까지 할 수 있었다.
2. 글자와 버튼이 읽고 누르기 편했다.
3. 어떤 정보를 더 입력해야 하는지 이해됐다.
4. 이 앱이 세금이나 법적 결론을 대신 내려 주지 않는다는 점이 분명했다.
5. 리포트를 세무사·변호사 상담에 가져가고 싶다.
6. 입력한 정보가 내 기기에만 저장된다는 점이 안심된다. (서버 저장이었다면 쓰겠는가? 별도 질문)

주관식: 가장 헷갈린 단어, 있었으면 하는 기능 1개, 빼도 되는 화면 1개.

## 5. 가격 의향 (앱 "내 데이터 → 파일럿 조사용" 라디오 사용)

- 질문: "이 리포트에 얼마까지 낼 의향이 있습니까?" (무료여야 함 / 49,000 / 89,000 / 129,000 / 돈을 내고 쓰지 않겠다)
- 이어서 반드시 이유를 묻는다: "그 금액을 고른 이유는?", "지금 상담 한 번에 얼마를 쓰고 있거나 쓸 것 같습니까?"
- 주의: 말로 한 의향은 실제 결제보다 과대 평가되는 경향이 있다. 이 값은 **방향 확인용**이다.

## 6. 전문가 인터뷰 질문 (30분)

1. 상담 전에 의뢰인이 가져오면 좋은 자료는 무엇입니까? 이 리포트에 빠진 것은?
2. 이 리포트가 의뢰인에게 오해를 줄 수 있는 표현이 있습니까? (특히 "합산 검토 대상" 표시, 기한 안내, 유언 안내)
3. 이 서비스가 법률·세무 자문으로 보일 위험이 있는 지점은 어디입니까?
4. 의뢰인이 이런 자료를 가져온다면 상담 시간이나 비용에 영향이 있습니까?
5. 유료로 판매한다면 어떤 형태(건당·구독·전문가 제휴)가 현실적입니까?

## 7. 합격선 (사전 설정, 결과를 본 뒤 바꾸지 않는다)

| 지표 | 목표 | 못 미치면 |
|---|---|---|
| T1–T4를 도움 없이 완료한 이용자 | 5명 중 4명 이상 | 입력 흐름·문구 재설계 |
| 사후 질문 4번(세금·법적 결론 오해 없음) 평균 | 4.0 이상 | 고지 문구와 시나리오 화면 재설계 |
| 사후 질문 5번(상담에 가져가고 싶다) | 5명 중 3명이 4점 이상 | 가치 가설 재검토 |
| 전문가 | 법적 오해 소지 지적 사항 목록화, 수정 후 재확인 | 해당 기능 삭제 검토 |

## 9. 결과 반영 규칙

- 발견한 문제는 GitHub Issues에 "pilot" 라벨로 등록한다.
- 합격선 미달 항목은 다음 수정에서 우선 처리하고, 수정 전후 결과를 같은 양식으로 다시 기록한다.
- 결과 요약(표본 수, 한계 포함)을 노션 프로젝트 허브에 남긴다. 5명 결과를 시장 전체로 해석하지 않는다.
